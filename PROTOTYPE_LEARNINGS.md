## 3. Surprises, Architectural Constraints & Document Corrections Discovered

### Surprise 1: `otelcol_exporter_send_failed_*` (and `sent_*`) Are 2x Double-Counted Unless Filtered by `exporter`
- **Root Cause**: In `go.opentelemetry.io/collector/processor/queuebatchprocessor@v0.162.0/processor.go:54`, `queuebatchprocessor` is implemented by calling `exporterhelper.NewLogs` / `NewMetrics` / `NewTraces`! Consequently, `queue_batch/default_gcp_destination_batch_logs` wraps `next.ConsumeLogs` (`otlp_grpc/default_gcp_destination`) in its own `exporterhelper` `obsReportSender`.
- **Empirical Impact**: When `otlp_grpc/default_gcp_destination` fails to export a batch of `6` log records (`codes.InvalidArgument`), **both** `exporter="otlp_grpc/default_gcp_destination"` (`6`) and `exporter="queue_batch/default_gcp_destination_batch_logs"` (`6`) increment `otelcol_exporter_send_failed_log_records` (unfiltered sum = `12`, a **2x overcount**). Conversely, `otelcol_exporter_enqueue_failed_*` is only emitted by `queue_batch/*` (because `sending_queue` is disabled on `otlp_grpc/default_gcp_destination`).
- **Required Fix in Tab 2 (`tango_onepager_2_gboc_self_o11y.md` Lines 59, 62)**: The Total Drop Rate UI badge and Cloud Monitoring Alert query (`rate(otelcol_exporter_send_failed_*) + rate(otelcol_exporter_enqueue_failed_*) + rate(otelcol_receiver_refused_*)`) **MUST** filter `otelcol_exporter_send_failed_*` by `exporter !~ "queue_batch/.*"` (or `exporter =~ "otlp_grpc/.*"`), otherwise every downstream export failure is counted twice!

### Surprise 2: `block_on_overflow: true` Can Still Drop Data at Queue Entry (`enqueue_failed_* > 0`, `send_failed_* == 0`)
- **Root Cause**: In `exporterhelper/internal/queue/memory_queue.go`:
  1. Line 75 (`if elSize > mq.cap { return errSizeTooLarge }`) runs **before** checking `mq.blockOnOverflow` (line 112). If `sizer: items` or `sizer: bytes` is used and a single batch exceeds `queue_size`, `Offer()` rejects it immediately without blocking.
  2. Line 116 (`if err := mq.hasMoreSpace.Wait(ctx); err != nil { return nil, err }`) unblocks and returns `context.Canceled` / `context.DeadlineExceeded` whenever the upstream receiver's context expires while waiting for queue space.
- **Required Fix in Tab 2 (`tango_onepager_2_gboc_self_o11y.md` Line 30)**: Explicitly note both `errSizeTooLarge` (`memory_queue.go:75`) and caller context deadline expiration (`memory_queue.go:116`) as queue-entry drop paths that occur **even when `block_on_overflow: true` is configured**.

### Surprise 3: Live `telemetry.googleapis.com:443` Already Ingests All 5 `obsQueue` Metrics into `prometheus.googleapis.com/*` Today (Not `agent.googleapis.com/agent/*`)
- **Empirical Evidence**:
  - In `dashpole-dev`, sending collector-generated OTLP `MetricsService/Export` requests to `telemetry.googleapis.com:443` succeeds (`codes.OK`, `RejectedDataPoints = 0`) for all 5 `obsQueue` metrics and creates live time series under **`prometheus.googleapis.com/otelcol_exporter_{queue_size/gauge,queue_capacity/gauge,enqueue_failed_log_records/counter,enqueue_failed_metric_points/counter,enqueue_failed_spans/counter}`** (`valueType = DOUBLE`, `resource.type = "prometheus_target"`).
  - By contrast, querying `agent.googleapis.com/agent/*` in `dashpole-dev` returns only 10 legacy Ops Agent descriptors (`agent.googleapis.com/agent/{api_request_count,log_entry_count,request_count,uptime,...}`) and `404 NOT_FOUND` for `agent.googleapis.com/agent/otelcol_*`.
  - Furthermore, exporting with `SelfMetricsPolicy`'s raw `Service.Telemetry.Resource` attributes (`service.instance.id`, `gcp.fleet_id`, `gcp.project_id`) without the `resourcedetection/default_self_metrics` GCE location attribute (`cloud.availability_zone` / `cloud.region`) is rejected by `telemetry.googleapis.com:443` with `codes.InvalidArgument` (`"write for resource failed: Unrecognized region or location."`).
  - Finally, in `provider.go:456`, `metrics/default_self_metrics` is wired through the shared `queue_batch/default_gcp_destination_batch_metrics` processor. If the workload **metrics** queue saturates (`10/10` with `block_on_overflow: true`), self-metrics export itself will contend on `queue_batch/default_gcp_destination_batch_metrics` unless `SelfMetricsPolicy` exports directly to `otlp_grpc/default_gcp_destination` or uses a dedicated self-metrics queue.
